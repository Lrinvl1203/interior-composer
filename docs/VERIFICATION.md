## 후속 변경 — 한 문장 설치와 OpenAI 통일

수신자는 비전문가이며 API 설정은 나중에 한다는 최신 요청을 반영했다. `CODEX_INSTALL.md`의 한 문장으로 로컬 Codex가 소스 ZIP/Git 선택·검증된 사용자 공간 런타임·패키지·빌드·아이콘·실행을 맡는다. 기존 Python/Node를 사용할 수도 있고 없으면 프로젝트 내부에 준비한다. Git은 필수 아니다.

- 이미지 생성·가구 AI 추출·시각 검수의 모든 활성 호출은 OpenAI다. 빠른/정밀 모드는 같은 이미지 모델의 low/high 품질이며 BytePlus로 우회하지 않는다.
- 키가 없으면 설치와 입력 저장은 가능하고 유료 생성/추출은 UI에서 차단된다. 설치기/런처는 상위 Codex 프로세스의 키를 자동 사용하지 않는다.

- frontend **47개 통과**, 타입 검사와 프로덕션 빌드 통과. OpenAI-only 상태와 자동 선택 포트/Windows UTF8 BOM 검사도 포함한다.
- PowerShell 구문, SHA256 불일치 시 추출 금지, ZIP 경로 이탈 거부, 임시 바로가기 생성 검사 통과.

기존 검증 기록은 과거 기준점의 사실이며 최신 실제 모델 출력 검증으로 바꾸지 않는다. 이번 변경에서 실제 과금 요청은 보내지 않았다. 키·계정 권한을 연결한 뒤 실제 결과 품질은 별도로 확인해야 한다.

### 빈 수신자 환경의 실제 자동 설치

Git 메타데이터·가상환경·node_modules·`.env`가 없는 새 공백 경로에 배포 소스만 놓고 `bootstrap.ps1 -ForcePortableRuntimes -NoBrowser`를 실행했다. 호스트에 설치된 Python/Node를 무시하고, SHA256 검증한 uv 0.13.0/Node 22.23.3와 프로젝트 로컬 Python 3.13.16을 사용해 패키지·프로덕션 빌드·서버 시작까지 성공했다.

다른 설치가 점유한 기본 포트는 보존하고 새 포트로 자동 실행했다. 호출 결과는 `status=ready`, `apiKeyPending=true`, `providerStatus=pending`, `paidApiCallsMade=false`였다. 상위 셸에는 테스트용 비민감 키 값을 설정했지만 앱은 이를 가져오지 않았고, 설치 도중 키 입력을 요구하지 않았다.

실제 Chromium 화면에서 OpenAI-only 상태, API 후속 연결 안내, 입력을 준비해도 유료 생성 버튼이 비활성임을 확인했다. 키 없이 사진·마감·요청 저장과 새로고침 복원을 통과했고 모바일 가로 넘침/페이지 오류는 없었다. 재실행은 같은 정상 서버를 유지하고 `.env`의 해시도 보존했다. 임시 바탕화면 디렉터리의 시작/종료 바로가기 두 개가 이 설치의 실제 BAT를 가리키는 것을 확인했다. 그 설치의 STOP/START도 통과했다.

OpenAI 경로 전환 뒤 오프라인 브라우저 왕복 **12개를 다시 통과**했다. 별도 디자인 검토에서 API 없는 화면의 큰 시각 결함은 발견되지 않았다. 화면의 Before는 비민감 도형 fixture이며 실제 모델 결과를 뜻하지 않는다. 모든 설치/테스트 자료와 다운로드 런타임은 공개 Git에서 제외한다.
